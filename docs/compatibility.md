# Mermaid version compatibility

MermaidDotNet generates Mermaid text. The Mermaid renderer you use must support that text.

**Set `TargetMermaidVersion` to the version of Mermaid that will render your diagrams.** The library does not detect, install, or upgrade your renderer.

By default:

- The target is **Mermaid 11.4**.
- Compatibility checks are enabled (`MermaidCompatibilityMode.Strict`).
- Features and settings that need a newer version are rejected.
- Features and settings that are no longer supported in the target version are also rejected.

For example, Gantt vertical markers need Mermaid 11.7. If your renderer is 11.7, configure the builder like this:

```csharp
var options = new MermaidDotNetOptions
{
    TargetMermaidVersion = MermaidVersion.V11_7
};

string diagram = Mermaid.GanttDiagram(options: options)
    .AddVerticalMarker("Release", new DateTimeOffset(2026, 1, 1, 0, 0, 0, TimeSpan.Zero))
    .Build();
```

Changing the target only changes the compatibility checks. It does not change the generated syntax or make an older renderer support newer features.

## Compatibility modes

| Mode | Behavior |
| --- | --- |
| `Strict` (default) | Rejects features that are not yet available or are no longer supported in the target version. This includes configuration settings. |
| `Unchecked` | Skips feature compatibility checks. The generated text may not work with your renderer. |

Neither mode changes input validation or sanitization. In particular, `ValidateInputs = false` does **not** disable compatibility checks.

### Tested versions

The parser integration tests run against **Mermaid 11.13**. This is the value of `MermaidCompatibility.LatestTestedVersion`.

You can select a newer target, including Mermaid 12, in strict mode. The library still checks the known version requirements. However, passing those checks is not a guarantee that your diagram works in an untested Mermaid release.

## Feature matrix

The versions below apply to **the text generated by MermaidDotNet**, not necessarily the first Mermaid release that offered the feature.

### Diagram types

These requirements are checked by `Build()`. Individual features within a diagram can require a newer version.

| Diagram | Minimum target for `Build()` |
| --- | --- |
| Kanban | 11.4 |
| Packet | 11.9 |
| Block, Sankey, XY | 11.10 |
| All other implemented diagram types | 11.0 |

**Why do some diagrams need a newer target than their original Mermaid release?** This library generates the headers `packet`, `block`, `sankey`, and `xychart`. Older Mermaid versions required headers ending in `-beta`. The library does not switch to those older headers when you select an older target.

### Builder features

The table lists the **minimum target needed to generate a complete diagram using each feature**. It accounts for both the feature and the diagram type. Other features or configuration settings you add may require a newer target.

Feature checks run when you call the method, before it adds the feature. The diagram-type check runs during `Build()`.

| Diagram type | Feature | Minimum target | Method or option |
| --- | --- | --- | --- |
| Flowchart | Expanded node shapes | 11.3 | `AddNodeWithExpandedShape()`; every `ExpandedNodeShape` value |
| Flowchart | Per-edge curves | 11.10 | `AddLink()` or `AddLinkChain()` with a non-null `curveStyle`; every `CurveStyle` value |
| Gantt | Vertical markers | 11.7 | `AddVerticalMarker()` |
| Packet | Bits syntax (`+<count>`) | **11.9** | `AddFieldWithBits()` |
| State | Hyperlinks, with or without a tooltip | 11.7 | `AddStateLink()` |
| Sequence | Participant shapes with display names | 11.13 | `AddMember()` or `SendCreateMessage()` with `Boundary`, `Control`, `Entity`, `Database`, `Collections`, or `Queue` |
| Class | Dotted namespace names, such as `Company.Product` | 11.3 | `AddNamespace()` |
| Class | Nested namespace blocks | 11.15 | `AddNamespace()` inside another namespace callback |
| Entity relationship (ER) | Multiline relationship labels | 11.1 | `AddRelationship()` with `<br/>` or `<br />`, including newlines converted by sanitization |

### Typed configuration

These checks run on every `Build()`. Property paths below start at `MermaidConfig`.

| Setting | Minimum target | Removed in |
| --- | --- | --- |
| `Elk.CycleBreakingStrategy` (every enum value) | 11.1 | — |
| `Kanban` section | 11.4 | — |
| `Journey.TitleColor`, `Journey.TitleFontFamily`, `Journey.TitleFontSize` | 11.7 | — |
| `XYChart.ShowDataLabel` | 11.7 | — |
| `Flowchart.DefaultRenderer` | 11.0 | 12.0 |
| `Class.DefaultRenderer` | 11.0 | 12.0 |
| `State.DefaultRenderer` | 11.0 | 12.0 |

An explicitly assigned value is checked even if it is `false`, zero, or the default enum value. For example, `ShowDataLabel = false` still needs 11.7. Leave a property `null` to omit it.

Every builder checks all supplied configuration sections, including sections for other diagram types. For example, a flowchart builder will reject incompatible `Journey` settings if you include them in its configuration.

## Resolving failures

A compatibility failure throws `MermaidException` with reason `IncompatibleVersion`. The message names the feature, your target, the required versions, and how to resolve the problem.

Choose one of these approaches:

1. **Use a supported renderer version and set the target to match.** Raising the target alone does not upgrade your renderer.
2. **Remove or replace the feature.** For example, use `AddNode()` instead of expanded flowchart shapes, ordinary participants/actors instead of newer sequence shapes, or flat namespaces instead of nested ones. For per-edge curves, omit `curveStyle` or use diagram-wide `Flowchart.Curve` instead.
3. **Use `Unchecked` deliberately.** This allows generation without feature checks. It does not make the output compatible.

### Migrating `DefaultRenderer` for Mermaid 12

Mermaid 12 no longer supports the flowchart, class, or state `DefaultRenderer` settings. Strict targets of **12.0 or later reject any of those settings**, regardless of their value.

Remove those settings and use top-level `MermaidConfig.Layout` instead:

```csharp
var options = new MermaidDotNetOptions
{
    TargetMermaidVersion = MermaidVersion.V12_0
};
var config = new MermaidConfig
{
    Layout = "elk" // or "dagre"
};

string diagram = Mermaid.Flowchart(config: config, options: options)
    .AddNode("Start", out _)
    .Build();
```

A deprecated setting is not necessarily removed. For example, `Flowchart.HtmlLabels` was deprecated in 11.13 but remains supported in Mermaid 12.
